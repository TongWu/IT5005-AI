# 5 - Search Algorithms
## 5.1 - Motivation
![image.png](https://images.wu.engineer/images/2024/04/25/202404252023313.png)
逻辑智能体（agent）是如何实现的。智能体通过对环境的感知来创建“感知语句”（percept statements），这些语句被加入到知识库（Knowledge Base，简称KB）中。然后，智能体应用推理规则（inference rules）来理解周围的世界，例如在Wumpus世界中判断(2, 2)方格是否安全。最后，智能体会根据目标来制定计划，如探索迷宫、射杀Wumpus或者取得金子等。
1. **感知与知识库**: 智能体首先通过感官（如视觉、听觉等）感知周围的环境，并将这些感知转换为明确的描述性语句，这些语句被存储在知识库中。知识库是智能体存储所有已知信息的数据库，用于后续的推理过程。
2. **应用推理规则**: 知识库中的信息可以通过逻辑推理来分析和处理。例如，智能体可能使用模态逻辑、条件逻辑等形式的推理来确定某个特定方块是否安全，或者预测某个行为的后果。
3. **规划与执行**: 一旦智能体通过推理得到必要的信息，它就会根据其目标制定行动计划。这个过程可能包括路径规划、决策制定以及策略执行等步骤，以确保能够有效安全地达成目标。
![image.png](https://images.wu.engineer/images/2024/04/25/202404252027876.png)
- 假设传感器检测到闪光，则意味着某个位置可能有金子。此时，代理需要执行以下操作：
1. 拾取金子，可以通过简单的规则实现
2. 返回起点，这需要生成一系列指令，以从当前的位置安全地返回起点。
- 使用逻辑执行这种路径规划非常困难，因为这通常涉及到序列决策，这在逻辑框架中不易处理
![image.png](https://images.wu.engineer/images/2024/04/25/202404252030110.png)
- 因此，需要引入**规划(Planning)** 的概念来解决这个问题。假设代理对世界有*全面视角*的情况下，即世界中没有隐藏的未知元素，规划可以被建模成一个*搜索问题*。搜索算法可以分为两大类：
	1. **无信息搜索(Uninformed Search)**：我们没有关于距离目标有多近或我们的移动有多好的信息
	2. **有信息搜索(Informed Search)**：每一步都会得到关于接近目标的反馈，或者关于移动效果的信息

## 5.3 - The Search Problem
![image.png](https://images.wu.engineer/images/2024/04/25/202404252038570.png)
- 解决问题的战略可以分为以下几个部分：
	1. 起始状态($S_0$): 解决问题开始于一个初始的状态，这是问题的起点
	2. 应用一系列动作：从初始状态开始，应用一系列*动作*来改变状态。这一系列的动作被称为*路径(Path)*，路径是从起始状态到目标状态的一系列动作的集合
	3. 达到目标状态集$G$：通过应用路径中的动作，最终达到一个或多个预定义的目标状态，目标状态是问题的结束点。
	4. 最小化代价：在执行路径的过程中，通常希望最小化某种形式的代价。这可能涉及时间、资源消耗、风险或其他任何重要的量度。
搜索和规划算法在解决实际问题时常常会遇到的挑战，特别是在复杂或大规模环境中：
 1. 状态空间可能极大
	- **指数增长**：每个动作如果产生两个新的选项，那么经过 𝑛 步之后，状态空间的大小会以指数形式增长为 $2^n$。这种情况在多数实际问题中非常常见，因为每一步都可能有多个选择，导致可能的状态数量迅速增加。这种指数级增长的状态空间称为“状态空间爆炸”，是许多搜索算法面临的主要挑战。
 2. 并非所有动作都能导向目标
	- **无效路径**：在具体的环境中，并不是所有的动作或决策都会接近目标。例如，在寻路问题中，某些路径可能会将代理带离目标而非接近目标。
 3. 资源耗尽
	- **有限资源**：在许多真实世界的应用中，代理在执行任务时会消耗资源，如燃料、时间、金钱等。如果路径规划没有考虑资源的限制，代理可能在达到目标前耗尽资源。例如，如果汽车只有足够的燃料行驶300英里，但规划的路径超过了这个距离，汽车将无法到达目的地。这要求规划算法不仅要考虑达到目标的路径，还要考虑路径的可行性和资源的可用性。
面对这些挑战，我们需要一个搜索算法可以：
- **合理扩展选择集**：搜索算法应能智能地扩展可行的动作或状态选择集，避免无目的地探索不可能或低效的路径。
- **检查是否能达到目标状态**：算法需要检查每个扩展出的新状态是否能够达到目标状态。这一点对于快速找到解决方案或早日终止无效搜索尤为重要。
- **尽量减少成本**：在搜索过程中，优选那些成本最低的路径，这通常涉及时间、资源消耗或其他形式的开销。
对搜索算法的正式定义：
- **输入**：搜索问题，包括起始状态、目标状态、可能的动作、每个动作的成本等。
- **输出**：
    - **成功时**：返回一系列达到目标状态的动作。这些动作构成了从起始状态到目标状态的有效路径。
    - **失败时**：如果找不到任何解决方案，返回失败的结果。
## 5.4 - Search Algorithms
1. **状态与节点**
	- **状态**：表示物理配置的一个描述。例如，在Wumpus World中，状态可以是“在L11方格，拥有一支箭”。
	- **节点**：搜索树中的一个数据结构，包含有关该节点的多个重要信息，如父节点、子节点、深度和路径成本。这些信息帮助算法追踪路径和管理搜索过程。
2. **节点间关系的重要性**
	- 了解节点间的父子关系对于生成从起始状态到目标状态的解决方案路径至关重要。搜索算法通常在到达目标节点后，通过追溯父节点来回溯整个路径。
3. **路径生成**
	- 从目标节点开始，依次查找每个节点的父节点，直到达到起始节点。这一过程将逆向展示出从起始状态到目标状态所需采取的全部动作。
	- 例如，如果路径是Arad到Sibiu到Fagaras到Bucharest，那么可以通过追溯每个城市的父节点来确定整个路径。在这个例子中，Bucharest的父节点是Fagaras，Fagaras的父节点是Sibiu，Sibiu的父节点是Arad。因此，路径可以逆向构建为从Arad出发到达Bucharest。
4. **动作生成**
	- 对于每个节点间的转移，可以定义一个动作来描述如何从一个节点达到另一个节点。在上述例子中，动作可以定义为：
	    - 𝑎(𝐴𝑟𝑎𝑑)=𝐺𝑜𝑆𝑖𝑏𝑖𝑢：从Arad到Sibiu的动作
	    - 𝑎(𝑆𝑖𝑏𝑖𝑢)=𝑔𝑜𝐹𝑎𝑔𝑎𝑟𝑎𝑠：从Sibiu到Fagaras的动作
	    - 𝑎(𝐹𝑎𝑔𝑎𝑟𝑎𝑠)=𝐺𝑜𝐵𝑢𝑐ℎ𝑎𝑟𝑒𝑠𝑡：从Fagaras到Bucharest的动作
## 5.5 - Uninformed Search Algorithms
> “无信息搜索算法”（uninformed search algorithms），又称为“盲目搜索算法”（blind search algorithms），是一类在搜索空间中寻找解决方案时**不使用关于目标状态距离或成本的任何先验信息**的算法。这类算法的主要特点是它们在搜索过程中仅依赖于问题本身的结构，而不利用任何特定于问题的知识。
- We will look at some uninformed search algorithms
	- Generalized Tree Search Algorithm (aka “Best-Fit”)
	- Breadth First Search (BFS)
	- Depth First Search (DFS)
	- Dijkstra’s Algorithm
### 5.5.1 General Tree Search Algorithm
“Generalized Tree Search Algorithm”或者有时被称作“Best-Fit”算法，其实不是一个特定的算法，而是一种算法框架，用于指导如何实现各种树搜索算法。这个框架提供了一个通用的方法，可以通过选定特定的数据结构和选择策略来实现广度优先搜索、深度优先搜索、最佳优先搜索等多种具体的搜索算法。在这个框架下，算法的行为将依赖于如何管理和扩展节点。
**结构与功能**
通常，广义树搜索算法包含以下几个核心部分：
1. **节点管理**：使用特定的数据结构（如队列、栈、优先队列）来存储待探索的节点。
2. **节点扩展**：每次从数据结构中取出一个节点，并生成其所有可能的后继节点。
3. **目标检测**：检查每个节点是否满足目标条件。
4. **重复/环检测**：确保不会重复探索相同的节点，避免无限循环。
5. **路径重建**：从找到的目标节点回溯到起始节点以构建解决方案路径。
**不同的搜索策略实现**
- **广度优先搜索（BFS）**：使用队列作为数据结构，始终从队列的前端取出节点进行扩展，保证了按层级顺序探索。
- **深度优先搜索（DFS）**：使用栈作为数据结构，始终从栈的顶部取出节点进行扩展，导致搜索沿树的一个分支深入。
- **最佳优先搜索（Best-First Search）**：使用优先队列，并根据某种评估函数（如启发式评估）来确定节点的优先级，始终扩展当前看起来最有希望的节点。

### 5.5.3 Depth First Search
- **策略**：扩展*最深的*未扩展节点，即纵向扩展
	- Implement fringe as a LIFO queue. Newly generated nodes are put in front.

#### DFS的问题
- 如果图中存在*循环*，DFS 可能会无限地扩展同一节点，因为它可能多次访问已经访问过的节点。这不仅会导致效率低下，而且在极端情况下可能导致算法无法继续进行。
	- **解决方案**：在实现DFS时，可以使用一个标记结构（如集合或哈希表）来记录已经访问过的节点，确保不会重复访问。
- 在*无限或非常深*的搜索空间中，DFS可能会沿着一个无限长的路径持续向下搜索，从而永远也找不到解决方案。
	- 广度优先搜索（BFS）不会遇到这个问题，因为它按层次扩展节点，首先检查所有同一层的节点，即使在有无限分支的情况下，每层节点的数量也是有限的，因此每一层都能完全检查。
#### IDS(迭代加深搜索)
为了解决DFS在处理无限深度问题时的不足，可以采用迭代加深搜索（IDS）。IDS的核心思想是：
- **逐层加深**：从执行一次深度限制为1的DFS开始，然后是深度限制为2的DFS，以此类推，每次都增加深度限制。
- **优点**：这种方法结合了DFS的空间效率和BFS的完备性。对于每个深度限制，IDS都完全探索该深度的所有节点，如果没有找到目标，就增加深度限制再次搜索。
- **效率**：尽管这听起来像是重复了许多工作，但实际上IDS在许多情况下都非常高效，尤其是在目标节点位于较浅深度时。此外，它也保证了找到最短路径，这是简单DFS所不具备的。
