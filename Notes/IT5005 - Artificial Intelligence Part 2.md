- **State**: A representation of the physical configuration.
  **状态(State)** 代表了某个问题的载体（例如数独问题的9 * 9矩阵）在问题中的某个**合法形态**。这种形态可以是在问题被解决时的形态(被解决的数独矩阵)，也可以是问题未被解决时的形态(包含空格(用0表示)的数独矩阵)。*合法形态*代表这需要符合问题的基本规则，例如对于数独问题，矩阵中的数字(1-9)需要在3 * 3方格，每一行和每一列中没有重复。

- **Goal State**: 定义问题求解的终点，即解决方案的状态。例如在数独问题中，目标状态是一个被完全填满的矩阵，其遵守数独规则。在路径搜索问题中，目标状态可能是机器人到达的特定位置。在棋类游戏中，最终状态是一方玩家获胜的棋盘布局。

1. **感知与知识库**: 智能体首先通过感官（如视觉、听觉等）感知周围的环境，并将这些感知转换为明确的描述性语句，这些语句被存储在知识库中。知识库是智能体存储所有已知信息的数据库，用于后续的推理过程。
2. **应用推理规则**: 知识库中的信息可以通过逻辑推理来分析和处理。例如，智能体可能使用模态逻辑、条件逻辑等形式的推理来确定某个特定方块是否安全，或者预测某个行为的后果。
3. **规划与执行**: 一旦智能体通过推理得到必要的信息，它就会根据其目标制定行动计划。这个过程可能包括路径规划、决策制定以及策略执行等步骤，以确保能够有效安全地达成目标。

## 5.3 - The Search Problem
![image.png](https://images.wu.engineer/images/2024/04/25/202404252038570.png)
- 解决问题的战略可以分为以下几个部分：
	1. 起始状态($S_0$): 解决问题开始于一个初始的状态，这是问题的起点
	2. 应用一系列动作：从初始状态开始，应用一系列*动作*来改变状态。这一系列的动作被称为*路径(Path)*，路径是从起始状态到目标状态的一系列动作的集合
	3. 达到目标状态集$G$：通过应用路径中的动作，最终达到一个或多个预定义的目标状态，目标状态是问题的结束点。
	4. 最小化代价：在执行路径的过程中，通常希望最小化某种形式的代价。这可能涉及时间、资源消耗、风险或其他任何重要的量度。
搜索和规划算法在解决实际问题时常常会遇到的挑战，特别是在复杂或大规模环境中：
 1. 状态空间可能极大
	- **指数增长**：每个动作如果产生两个新的选项，那么经过 𝑛 步之后，状态空间的大小会以指数形式增长为 $2^n$。这种情况在多数实际问题中非常常见，因为每一步都可能有多个选择，导致可能的状态数量迅速增加。这种指数级增长的状态空间称为“状态空间爆炸”，是许多搜索算法面临的主要挑战。
 2. 并非所有动作都能导向目标
	- **无效路径**：在具体的环境中，并不是所有的动作或决策都会接近目标。例如，在寻路问题中，某些路径可能会将代理带离目标而非接近目标。
 3. 资源耗尽
	- **有限资源**：在许多真实世界的应用中，代理在执行任务时会消耗资源，如燃料、时间、金钱等。如果路径规划没有考虑资源的限制，代理可能在达到目标前耗尽资源。例如，如果汽车只有足够的燃料行驶300英里，但规划的路径超过了这个距离，汽车将无法到达目的地。这要求规划算法不仅要考虑达到目标的路径，还要考虑路径的可行性和资源的可用性。
面对这些挑战，我们需要一个搜索算法可以：
- **合理扩展选择集**：搜索算法应能智能地扩展可行的动作或状态选择集，避免无目的地探索不可能或低效的路径。
- **检查是否能达到目标状态**：算法需要检查每个扩展出的新状态是否能够达到目标状态。这一点对于快速找到解决方案或早日终止无效搜索尤为重要。
- **尽量减少成本**：在搜索过程中，优选那些成本最低的路径，这通常涉及时间、资源消耗或其他形式的开销。
对搜索算法的正式定义：
- **输入**：搜索问题，包括起始状态、目标状态、可能的动作、每个动作的成本等。
- **输出**：
    - **成功时**：返回一系列达到目标状态的动作。这些动作构成了从起始状态到目标状态的有效路径。
    - **失败时**：如果找不到任何解决方案，返回失败的结果。
## 5.4 - Search Algorithms
1. **状态与节点**
	- **状态**：表示物理配置的一个描述。例如，在Wumpus World中，状态可以是“在L11方格，拥有一支箭”。
	- **节点**：搜索树中的一个数据结构，包含有关该节点的多个重要信息，如父节点、子节点、深度和路径成本。这些信息帮助算法追踪路径和管理搜索过程。
2. **节点间关系的重要性**
	- 了解节点间的父子关系对于生成从起始状态到目标状态的解决方案路径至关重要。搜索算法通常在到达目标节点后，通过追溯父节点来回溯整个路径。
3. **路径生成**
	- 从目标节点开始，依次查找每个节点的父节点，直到达到起始节点。这一过程将逆向展示出从起始状态到目标状态所需采取的全部动作。
	- 例如，如果路径是Arad到Sibiu到Fagaras到Bucharest，那么可以通过追溯每个城市的父节点来确定整个路径。在这个例子中，Bucharest的父节点是Fagaras，Fagaras的父节点是Sibiu，Sibiu的父节点是Arad。因此，路径可以逆向构建为从Arad出发到达Bucharest。
4. **动作生成**
	- 对于每个节点间的转移，可以定义一个动作来描述如何从一个节点达到另一个节点。在上述例子中，动作可以定义为：
	    - 𝑎(𝐴𝑟𝑎𝑑)=𝐺𝑜𝑆𝑖𝑏𝑖𝑢：从Arad到Sibiu的动作
	    - 𝑎(𝑆𝑖𝑏𝑖𝑢)=𝑔𝑜𝐹𝑎𝑔𝑎𝑟𝑎𝑠：从Sibiu到Fagaras的动作
	    - 𝑎(𝐹𝑎𝑔𝑎𝑟𝑎𝑠)=𝐺𝑜𝐵𝑢𝑐ℎ𝑎𝑟𝑒𝑠𝑡：从Fagaras到Bucharest的动作
## 5.5 - Uninformed Search Algorithms
> “无信息搜索算法”（uninformed search algorithms），又称为“盲目搜索算法”（blind search algorithms），是一类在搜索空间中寻找解决方案时**不使用关于目标状态距离或成本的任何先验信息**的算法。这类算法的主要特点是它们在搜索过程中仅依赖于问题本身的结构，而不利用任何特定于问题的知识。
- We will look at some uninformed search algorithms
	- Generalized Tree Search Algorithm (aka “Best-Fit”)
	- Breadth First Search (BFS)
	- Depth First Search (DFS)
	- Dijkstra’s Algorithm
### 5.5.1 General Tree Search Algorithm
“Generalized Tree Search Algorithm”或者有时被称作“Best-Fit”算法，其实不是一个特定的算法，而是一种算法框架，用于指导如何实现各种树搜索算法。这个框架提供了一个通用的方法，可以通过选定特定的数据结构和选择策略来实现广度优先搜索、深度优先搜索、最佳优先搜索等多种具体的搜索算法。在这个框架下，算法的行为将依赖于如何管理和扩展节点。
**结构与功能**
通常，广义树搜索算法包含以下几个核心部分：
1. **节点管理**：使用特定的数据结构（如队列、栈、优先队列）来存储待探索的节点。
2. **节点扩展**：每次从数据结构中取出一个节点，并生成其所有可能的后继节点。
3. **目标检测**：检查每个节点是否满足目标条件。
4. **重复/环检测**：确保不会重复探索相同的节点，避免无限循环。
5. **路径重建**：从找到的目标节点回溯到起始节点以构建解决方案路径。
**不同的搜索策略实现**
- **广度优先搜索（BFS）**：使用队列作为数据结构，始终从队列的前端取出节点进行扩展，保证了按层级顺序探索。
- **深度优先搜索（DFS）**：使用栈作为数据结构，始终从栈的顶部取出节点进行扩展，导致搜索沿树的一个分支深入。
- **最佳优先搜索（Best-First Search）**：使用优先队列，并根据某种评估函数（如启发式评估）来确定节点的优先级，始终扩展当前看起来最有希望的节点。

#### DFS的问题
- 如果图中存在*循环*，DFS 可能会无限地扩展同一节点，因为它可能多次访问已经访问过的节点。这不仅会导致效率低下，而且在极端情况下可能导致算法无法继续进行。
	- **解决方案**：在实现DFS时，可以使用一个标记结构（如集合或哈希表）来记录已经访问过的节点，确保不会重复访问。
- 在*无限或非常深*的搜索空间中，DFS可能会沿着一个无限长的路径持续向下搜索，从而永远也找不到解决方案。
	- 广度优先搜索（BFS）不会遇到这个问题，因为它按层次扩展节点，首先检查所有同一层的节点，即使在有无限分支的情况下，每层节点的数量也是有限的，因此每一层都能完全检查。
#### IDS(迭代加深搜索)
为了解决DFS在处理无限深度问题时的不足，可以采用迭代加深搜索（IDS）。IDS的核心思想是：
- **逐层加深**：从执行一次深度限制为1的DFS开始，然后是深度限制为2的DFS，以此类推，每次都增加深度限制。
- **优点**：这种方法结合了DFS的空间效率和BFS的完备性。对于每个深度限制，IDS都完全探索该深度的所有节点，如果没有找到目标，就增加深度限制再次搜索。
- **效率**：尽管这听起来像是重复了许多工作，但实际上IDS在许多情况下都非常高效，尤其是在目标节点位于较浅深度时。此外，它也保证了找到最短路径，这是简单DFS所不具备的。

### 5.5.4 Dijkstra’s Algorithm
#### Dijkstra算法的工作原理：
1. **初始化**：
    - 选择图中的起始顶点作为源点。
    - 将所有顶点的最短路径估计值设为无穷大，除了源点自身，其值设为0。
2. **设置已访问集合**：
    - 创建一个空集合，用于存放已经找到最短路径的顶点。
3. **路径更新和顶点选择**：
    - 在未完成的顶点中，选择一个当前距离源点最近（即最短路径估计值最小）的顶点。
    - 更新该顶点的邻接顶点的最短路径估计值。对于每个邻接顶点，如果通过当前顶点到该邻接顶点的路径比已知的路径更短，就更新它的最短路径估计值。
    - 将当前顶点加入到已访问集合中。
4. **重复过程**：
    - 重复选择未完成顶点中最近的顶点和更新路径的过程，直到所有顶点都被访问过，或者剩余未访问的顶点的最短路径估计值都是无穷大（即从源点不可达）。
5. **结束**：
    - 算法完成后，可以得到从源点到所有其他顶点的最短路径长度。
#### 特点和实际应用：
- **非负权重限制**：Dijkstra算法要求图中所有边的权重都是非负的。这是因为算法依赖于“已知最短路径总是在前”的原则，如果存在负权重，算法可能会产生错误的结果。
- **效率**：算法的时间复杂度依赖于使用的数据结构，通常实现时使用优先队列，复杂度可达到O((V+E)logV)，其中V是顶点数，E是边数。
- **广泛应用**：Dijkstra算法因其实现简单和高效，在实际中被广泛用于路由算法和网络中的路径发现等场景。

## 5.6 - Informed Search Algorithms
启发式搜索（Informed Search），这是一种在搜索过程中利用额外信息来引导搜索方向的算法类型。启发式搜索与无信息搜索的主要区别在于，它使用一个启发式函数 ℎh 来提供从当前节点到目标节点的估计成本。这种估计帮助算法更有效地确定搜索的优先级，从而提高搜索效率。
#### 启发式函数 ℎ
启发式函数 ℎ(𝑛) 是一个估计值，表示从节点 𝑛 到目标节点的预计最小成本。这个函数不必完全准确，但是它提供的信息越准确，搜索算法的效率通常越高。例如：
- 在罗马尼亚问题中，如果目标是到达布加勒斯特，一个好的启发式函数可能是每个城市到布加勒斯特的直线距离。这种距离通常称为“直线距离”或“欧几里得距离”，虽然不一定是实际行驶的最短路径，但提供了一个不错的估计，可以帮助算法决定哪些路径可能更接近目标。
#### 启发式搜索的工作方式
启发式搜索使用启发式函数 ℎh 来引导搜索过程：
- **单纯使用 ℎ（纯启发式搜索，如最佳优先搜索）**：这种搜索方法只考虑到达目标的估计成本，不考虑从起点到当前节点的实际成本。它倾向于优先扩展那些看起来离目标最近的节点。
- **结合 ℎh 和到达当前节点的成本 𝑔（如A* 搜索算法）**：A* 搜索算法使用函数 𝑓(𝑛)=𝑔(𝑛)+ℎ(𝑛) 来引导搜索，其中 𝑔(𝑛) 是从起始节点到节点 𝑛 的实际路径成本，而 ℎ(𝑛) 是从节点 𝑛 到目标的估计成本。这种结合确保了搜索既考虑了到达目标的总成本，也尽可能优化路径成本，从而找到成本最优的最短路径。
### 5.6.1 Greedy Best First Search
Greedy Best First Search（贪婪最佳优先搜索）使用启发式函数来引导搜索过程，尝试以最快的方式到达目标节点。这种算法主要关注在每一步中选择**似乎最接近目标的节点**，从而快速找到目标，但**不一定保证找到的是最短路径**。
#### 工作原理
Greedy Best First Search的工作原理如下：
1. **启发式函数 ℎ(𝑛)h(n)**：这个函数用于估计从节点 𝑛n 到目标节点的距离或成本。该函数是算法的核心，因为它直接影响节点选择的优先级。
2. **节点选择**：在每一步，算法都选择启发式函数值最小的节点进行扩展，即选择看似最接近目标的节点。
3. **开放列表**：算法维护一个称为“开放列表”的结构（通常是优先队列），其中包含待扩展的节点。这个列表按照启发式函数的值排序，每次从中取出启发式值最小的节点进行扩展。
4. **重复过程**：继续选择和扩展节点，直到找到目标节点或者开放列表为空（这意味着路径不存在）。
#### 例子
![image.png](https://images.wu.engineer/images/2024/04/26/202404261435100.png)
- 在这个图像中，左侧的列表标明每个城市到Bucharest的直线距离，右侧图片标明每个可连接城市之间的距离。
	- 左侧的列表可以被看作*启发式函数*，其标明了每次行动的代价（即当前城市到目标城市的直线距离）
- GBFS在每次做选择时，总是(盲目地)选择直线距离最近的城市。
![image.png](https://images.wu.engineer/images/2024/04/26/202404261437021.png)
- 这样的结论可能**不是最佳的**。我们选择Arad-Sibiu-Fagaras-Bucharest。这个路径一共有450 miles的距离
	- 最佳方案是 Arad-Sibiu-Rimincu Vilcea-Pitesti-Bucharest，这个路径只有418 miles
- 这是因为**贪婪算法(Greedy Algorithm)不会顾及全局最优，只选择局部最优**
### 5.6.2 A* Search
A* 搜索恁找到从起始节点到目标节点的*最短路径*，同时维持搜索效率。A* 算法结合了贪婪最佳优先搜索的高效性和广度优先搜索的全面性，通过一个评估函数来平衡这两者，使得在寻找最短路径的同时尽可能减少搜索所需的步骤。
#### 工作原理
A* 搜索使用以下的评估函数来决定节点的扩展顺序：
$f(n) = g(n) + h(n)$
其中：
- 𝑔(𝑛)是从起始节点到节点 𝑛 的实际路径成本。
- ℎ(𝑛)是从节点 𝑛 到目标节点的启发式估计成本（通常是一个欧几里得距离、曼哈顿距离或其他合适的启发式函数）。

1. **初始化**：
    - 将起始节点放入开放列表（通常是一个优先队列，按 𝑓(𝑛) 值排序）。
2. **循环直到找到目标或开放列表为空**：
    - 从开放列表中取出 𝑓(𝑛)值最小的节点 𝑛。
    - 如果 𝑛 是目标节点，通过回溯 𝑛 的父节点来重建路径。
    - 对 𝑛 的每个邻接节点 𝑚，计算 𝑓(𝑚)=𝑔(𝑚)+ℎ(𝑚)：
        - 如果 𝑚 不在开放列表中，加入列表。
        - 如果 𝑚 已在开放列表中但新的 𝑔(𝑚) 更小，更新 𝑚 的 𝑔(𝑚)，并重新排序开放列表。
3. **结束**：
    - 如果开放列表为空但未找到目标，则没有可达路径。

### 5.6.3 Admissibility of Search Heuristics
#### 可采纳性(Admissibility)
- 为了保证算法能找到最优解，启发式函数必须对实际到达目标的成本进行**低估**（never overestimate）。这样的启发式函数被称为“可采纳的”（admissible）。
	- 例如，使用到布加勒斯特的直线距离作为启发式函数是可采纳的，因为实际的道路因转弯、绕过湖泊和山脉等原因，距离总是比直线距离长。
##### 可采纳性的证明
![image.png](https://images.wu.engineer/images/2024/04/26/202404261457245.png)
A* 算法可采纳启发式函数确保找到最优解的证明过程：
1. 假设存在一条最优路径，其成本是 𝐶∗。
2. 假设A* 算法找到了一条非最优解的路径，其成本为 𝐶，并且 𝐶>𝐶∗。
3. 存在一个节点 𝑛，它在最优路径上但未被扩展。
4. 对于任何节点 𝑛，评估函数 𝑓(𝑛)=𝑔(𝑛)+ℎ(𝑛)的值小于 𝐶∗（否则，节点 𝑛 就会被扩展）。
5. 对于最优路径上的节点 𝑛，𝑓(𝑛)=𝑔∗(𝑛)+ℎ(𝑛)，因为 𝑛 在最优路径上。
6. 因为 ℎ(𝑛) 是可采纳的，ℎ(𝑛)≤ℎ∗(𝑛)。
7. 所以 𝑓(𝑛)≤𝑔∗(𝑛)+ℎ∗(𝑛)=𝐶∗，这与我们的第4点矛盾。
因此，如果启发式函数是可采纳的，A* 算法不可能产生次优解，这个假设是错误的。
#### 一致性（Consistency）
- 另一个属性是一致性，即对于任何节点 𝑛，其启发式成本 ℎ(𝑛) 应该小于等于从 𝑛 到任何邻接节点 𝑛′ 的实际成本 𝑐(𝑛,𝑎,𝑛′) 加上 𝑛′ 的启发式成本 ℎ(𝑛′)。
	- ![image.png](https://images.wu.engineer/images/2024/04/26/202404261458546.png)
- 所有一致的启发式都是可采纳的，但反之则不然。这意味着一致性是一个比可采纳性更强的条件。

# 6 - Adversarial Search
## 6.1 - Local Search Algorithm
局部搜索算法是一种用于解决优化问题的启发式搜索方法，它在候选解的局部邻域中搜索更优的解。不同于其他搜索算法（如A* 或深度优先搜索）需要维护一个搜索树或图，并在整个解空间中进行搜索，局部搜索算法通常从一个单一的候选解出发，然后迭代地在其邻域中探索，以寻找更好的解。
##### 特点
- **启发式方法**：局部搜索算法通常利用问题的特性和启发式知识来引导搜索，减少搜索空间。
- **不保证最优性**：大多数局部搜索算法不能保证找到全局最优解，但它们能在合理的时间内找到良好的局部最优解。
- **内存效率**：与其他搜索方法相比，局部搜索算法在空间复杂度上通常更高效，因为它们不需要维护整个搜索树或图。
## 6.2 - n-queens problem
n-queens问题是一个经典的组合问题，问题的目标是在一个 𝑛×𝑛n×n 的棋盘上放置 𝑛n 个皇后，使得这些皇后之间互不攻击。在国际象棋中，皇后可以攻击同一行、列或对角线上的任何位置。因此，解决n-queens问题就是要找到一种放置方式，使得任何两个皇后都不在彼此的攻击范围内。
这个问题可以通过多种算法解决，包括局部搜索算法。实际上，局部搜索算法常用于较大的n-queens问题，特别是当 𝑛n 变得很大，而传统的回溯算法变得不切实际时。
### Hill-climbing search
- **爬山算法**：类似于梯度上升（或下降），在每次迭代中选择最好的邻居作为新的当前解，直到没有更好的邻居为止，即达到局部最高点（局部最优解）。
![image.png](https://images.wu.engineer/images/2024/04/26/202404261556701.png)
#### 初始配置
1. **生成初始解**：随机在棋盘上放置n个皇后，通常每一列放置一个皇后。
#### 评估函数
2. **定义评估函数**：评估函数用于计算每个皇后被其他皇后攻击的次数，整个棋盘的评估值是所有皇后被攻击次数的总和。爬山算法的目标是最小化这个评估值。
#### 迭代搜索
1. **选择最佳移动**：对每个皇后，尝试在其所在列的所有可能行中移动，选择那个能使评估函数值最小化的行。如果有多个最佳移动，则随机选择一个。
2. **移动皇后**：将皇后移动到评估函数值最小的那个位置。
3. **检查结束条件**：如果达到了一个状态，其中所有皇后的移动都不会导致评估函数值的减小，那么算法终止。这可能是全局最优解（所有皇后都不相互攻击），但更可能是局部最优解。
#### 问题
爬山算法可能会陷入局部最优解
![image.png](https://images.wu.engineer/images/2024/04/26/202404261603359.png)
#### 优化和变体
1. **重启策略**：一个常用的策略是在陷入局部最优解时重新开始（有时称为**随机重启(Random Start)爬山算法**）。
2. **随机行走 (Sideway move)**：为了避免局部最优，可以引入一定的随机性，允许算法偶尔选择非最优的移动。
3. **首选爬山**：这是爬山算法的一个变体，它首先考虑那些可能会导致评估函数显著改善的移动。

## 6.2 - Adversarial Search
### Adversarial Search Problems (aka games)
- **游戏问题**（Game Problems）：指的是有两个或多个对手（通常是两个玩家）相互竞争的情境，如国际象棋、围棋或井字棋。游戏问题的特点是每个玩家都试图最大化自己的收益（或胜率），同时考虑到对手也在尝试做同样的事情。
- **搜索问题**（Search Problems）：通常指的是找到从初始状态到目标状态的路径的问题。在非对抗搜索问题中，环境是静态的，不会随着代理的行动而改变。
- **效用最大化的对手**（Utility Maximizing Opponent）：在对抗性游戏中，对手也是理性的，并且会尝试最大化其自己的效用。效用是一个评估游戏状态好坏的数值指标。在游戏中，你需要对对手的每一种可能响应都有一个应对策略。
- **时间限制**（Time Limit）：由于对抗性游戏的复杂性，通常在实际情况中不可能在合理的时间内找到一个完美的目标（例如，找到一个必胜的完整游戏策略）。因此，我们往往需要在有限的时间内找到一个近似解，这需要算法能够迅速做出好的决策。
#### Zero-Sum Game
零和游戏是一种博弈论中的概念，指的是一个玩家的获益加上另一个玩家的损失**总和等于零**的情况。也就是说，一个玩家的每一分获益都是另一个玩家的损失。这种情况下的游戏没有“合作”的可能，玩家只能在对方的损失中寻找自己的利益。

在零和游戏中，通常有两类玩家：
1. **MAX玩家**：
    - MAX玩家的目标是最大化自己的获益。在博弈论的语境中，这通常意味着他们寻找那些能使得游戏的效用值（通常表示为分数、金钱或其他有价值的指标）最大化的策略。
2. **MIN玩家**：
    - MIN玩家的目标是最小化MAX玩家的获益，从而最大化自己的获益。因为是零和游戏，所以通过减少MAX玩家的收益，MIN玩家实际上是在增加自己的获益。

## 6.3 - Optimal (i.e., Minimax) decisions
- **Zero-sum game(零和游戏)**: 零和游戏指的是一个玩家的获益加上另一个玩家的损失**总和等于零**的情况。也就是说，一个玩家的每一分获益都是另一个玩家的损失。这种情况下的游戏没有“合作”的可能，玩家只能在对方的损失中寻找自己的利益。
- 在零和游戏中，通常有两类玩家：
	1. **MAX玩家**：
	    - MAX玩家的目标是最大化自己的获益。在博弈论的语境中，这通常意味着他们寻找那些能使得游戏的效用值（通常表示为分数、金钱或其他有价值的指标）最大化的策略。
	2. **MIN玩家**：
	    - MIN玩家的目标是最小化MAX玩家的获益，从而最大化自己的获益。因为是零和游戏，所以通过减少MAX玩家的收益，MIN玩家实际上是在增加自己的获益。
- **Strategy(策略)**: 在博弈论中，特别是在完全信息的游戏中，策略 𝑠 是玩家的一个完整行动计划，它详细说明了在游戏中可能到达的每一个节点玩家应该怎样行动。策略必须包括玩家在游戏的每个可能状态下将要执行的行动，即使这些状态在实际游戏中可能永远不会到达。
- **Winning Strategy**: 如果玩家1有一个策略 𝑠1∗​，对于玩家2的任何策略 𝑠2​，游戏最终都以玩家1获胜结束，那么这个策略 𝑠1∗​ 被称为赢的策略。在这种情况下，玩家1可以保证无论玩家2如何应对都能获胜。
- **Non-Losing Strategy**: 如果玩家1有一个策略 𝑡1∗​，对于玩家2的任何策略 𝑠2​，游戏最终都不会以玩家1输掉结束（即玩家1至少能够打成平局或赢得比赛），那么这个策略 𝑡1∗​ 被称为不输的策略。
- **Von Neumann’s Theorem**: 在像国际象棋这样的完全信息零和游戏中，三种情况只会有一种是真的：
	1. 白方有一个赢的策略$s^*_w$
	2. 黑方有一个赢的策略$s^*_b$
	3. 双方各自都有一个不输的策略
### Minimax算法
#### MAX 玩家
- **最大化最小收益**：MAX玩家的目标是最大化其可能获得的最小收益。这意味着MAX玩家在考虑所有可能的对手（MIN玩家）的反应后，选择一种策略，使得在最坏情况下的收益（即MIN玩家尽可能使MAX玩家收益最小化的情况）达到最大。简单来说，MAX玩家在考虑对手可能的最优反应（对MIN玩家而言）后，选择能保证自己获得最高最小收益的行动。
#### MIN 玩家
- **最小化最大收益**：MIN玩家的目标是最小化MAX玩家可能获得的最大收益。这意味着MIN玩家在考虑所有可能的对手（MAX玩家）的行动后，选择一种策略，使得在最坏情况下（即MAX玩家尽可能使自己的收益最大化的情况）对自己的损失达到最小。简单来说，MIN玩家尽力减少对手在最佳情况下能获得的收益。
#### 算法步骤
这种决策逻辑的应用可以通过Minimax算法来体现，该算法在对抗性博弈中非常普遍，尤其是在两人零和游戏中。算法如下：
1. **对每个可能的游戏行动，评估可能的未来结果**：这包括对当前玩家的所有可能行动进行评估，然后再递归地对对手的每个回应进行评估。
2. **递归**：对于每个行动，考虑所有可能的对手回应，然后对这些回应中的每一个，再考虑所有可能的回应，依此类推，直到到达游戏的终结状态。
3. **使用评估函数**：在游戏的终结状态，使用一个评估函数来给状态打分。对于MAX玩家，高分是好的；对于MIN玩家，低分是好的。
4. **回溯并选择最佳行动**：通过递归地回溯评分，MAX玩家选择在考虑对手最佳回应后自己得分最高的行动，而MIN玩家选择在考虑对手最佳回应后自己得分最低的行动
![image.png](https://images.wu.engineer/images/2024/04/26/202404262103617.png)
### 反向归纳(Backward Induction)
在算法步骤中我们看到，在每一个会和中，minimax算法都会递归的计算未来每一步对手的可能回应从而计算当前状态下的最佳动作。这种算法在面对巨大的树状结构时性能会非常差。这时我们需要用到**反向归纳**
反向归纳（Backward Induction）是一种在博弈论和决策理论中用来求解动态博弈（通常是顺序博弈）中的策略的方法。这种方法特别适用于那些决策步骤按时间顺序展开，且后一个决策依赖于前一个决策的结果的情况。在使用反向归纳时，我们从博弈的最后阶段开始分析，并逐步向前推进，从而确定每个阶段的最优策略。
#### 反向归纳的步骤
1. **识别最终决策**：首先查看博弈的最后一步，此时的决策者会考虑所有可能的选择，并评估每个选择的结果。
2. **选择最优策略**：在最后一步，决策者将选择能够最大化其效用的策略。由于这是博弈的最后一步，决策者的选择只基于此时的收益。
3. **向前一步推进**：接下来，分析倒数第二步的决策。在这一步，决策者需要预测最后一步的决策，并基于这个预测来选择当前步骤的最优策略。决策者会考虑所有可能的当前选择，对于每一种选择，都考虑接下来对手采取最优策略的情况。
4. **重复过程**：继续逐步向前推进，每一步都假定在其后的所有步骤中，所有决策者都会采取理性的、最优化自己利益的决策。
5. **首个决策**：当分析到第一步时，你将得到一个完整的策略序列，从第一步到最后一步，每一步的决策都考虑到了之后各步骤的最优反应。
## 6.4 - $\alpha$ - $\beta$ pruning
### Alpha-Beta 剪枝的基本原理
Alpha-beta 剪枝基于两个参数：alpha 和 beta。这两个参数分别代表在搜索过程中已发现的最佳路径上的最小评分（alpha）和最大评分（beta）。
- **Alpha（α）**：在MAX玩家的视角下，alpha 代表其可以确保的最低得分，也就是说，MAX玩家在游戏过程中不会接受比alpha更低的得分。
- **Beta（β）**：在MIN玩家的视角下，beta 代表其可以确保的最高得分，也就是说，MIN玩家在游戏过程中不会接受比beta更高的得分。
### 工作过程
1. **初始化**：在树的根节点开始，alpha 初始化为负无穷大（表示MAX玩家的得分没有下限），beta 初始化为正无穷大（表示MIN玩家的得分没有上限）。
2. **递归搜索**：通过递归地应用极小化极大算法，在每个节点计算最优策略。同时，每当在树的某一路径上发现一个可能的得分时，都会更新alpha 或 beta 的值。
3. **剪枝决策**：
    - 当在某个节点的搜索中发现alpha 值大于或等于beta 值时，就可以停止在该节点进一步搜索。这是因为，对于MIN玩家而言，任何高于beta 的得分都是不可接受的（因为它们已经找到了更好的选项），而对于MAX玩家而言，任何低于alpha 的得分也是不可接受的。
    - 这意味着在当前的搜索分支中，已经不存在能够影响最终决策的更好或更坏的选项，因此继续搜索这条分支是无效的。
### 优点和效果
Alpha-beta 剪枝能够显著减少需要评估的节点数量，尤其是在搜索树的上层就能发现强力走法的情况下。这不仅提高了搜索的速度，还能在有限的时间内更深入地搜索，从而提高了决策的质量。虽然它最佳情况下可以将节点数减少到原来的平方根级别，但实际效果取决于节点的排列和树的结构。
## 6.5 - Imperfect, real-time decisions
### Evaluation Function
评估函数（Evaluation Functions），在人工智能和计算机博弈领域中，尤其是在对抗性游戏如国际象棋、围棋等中，是一种用来估计给定游戏状态对于某个玩家的优势程度的函数。这种函数对于开发能够进行高级策略和决策的游戏AI至关重要，因为它们提供了一种方法来量化非终结游戏状态的价值，即在游戏尚未结束时如何评价当前局面的好坏。
#### 作用和应用
评估函数通常在以下几个方面发挥作用：
1. **决策辅助**：在搜索算法（如Minimax或Alpha-Beta剪枝等）中，评估函数帮助AI决定哪些移动更有利。算法使用这些函数在没有达到终结状态（游戏结束）的情况下估计不同行动方案的效果。
2. **非终结状态的评估**：在许多游戏中，可能存在成千上万种不同的非终结状态，而在有限的计算时间内，AI无法探索到所有可能的游戏结局。评估函数可以提供一个合理的近似，表明在当前步骤中，各种可能行动的相对优劣。
#### 实现方法
评估函数的实现通常依赖于游戏的特定特性和规则，但大体上可以分为以下几种类型：
1. **启发式评估**：在棋类游戏中，评估函数可能会考虑棋子的数量、棋子的位置、控制的区域、棋子间的协同作用等因素。例如，在国际象棋中，评估函数可能会给每种棋子一个基础分值，加分项可能包括棋子的活动范围、保护关系、威胁对手的棋子等。
2. **基于特征的评估**：在更复杂的游戏或应用中，评估函数可能会包含多个相关特征的加权和，这些特征根据其对游戏结果的预测影响被赋予不同的权重。
3. **机器学习方法**：近年来，通过机器学习训练的评估函数成为可能，特别是在围棋等领域通过深度学习训练的模型，能够直接从游戏状态的表征中学习评估函数。这种方法可以捕捉到人类或传统方法难以直接编码的复杂模式。
